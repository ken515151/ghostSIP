# GhostSIP

Secondary SIP server that restores accurate missed-call entries on Polycom VVX handsets for caller-abandoned ring-group calls on VoIPstudio.

VoIPstudio sends `CANCEL` with `Reason: SIP;cause=200;text="Call completed elsewhere"` even when nobody answered, which makes the phones suppress the missed-call entry. GhostSIP injects a "ghost call" (INVITE → ring → CANCEL, no cause=200) carrying the abandoned caller's real number, so the phone logs a native missed call. Tapping the entry calls back through a dedicated VoIPstudio "trunk-back" seat.

**Read [GhostSIP-handoff.md](GhostSIP-handoff.md) first** — it is the authoritative spec (v2, design finalised). This repo turns that spec into deployable artifacts.

## Configuration is GUI-driven

You do **not** hand-edit config files in normal operation. After deploying (see
[docs/deployment.md](docs/deployment.md)), everything is managed in the Django
admin — which is **not internet-facing**: the public domain serves only the
VoIPstudio webhook, and the admin is reached through an SSH tunnel to loopback
(`ssh -L 8100:127.0.0.1:8100 …` → http://127.0.0.1:8100/admin):

- **Settings** — webhook / ARI / trunk-back credentials, ghost-call ring & dedup.
- **Handsets** — add a VVX, auto-generate its SIP secret; the panel writes
  Asterisk's `pjsip.conf` and reloads it for you.
- **Events** — persisted, searchable activity log (webhooks, injections, security, lockdown) that survives restarts.
- **Pushover alerts** — high-priority push on SIP brute-force attempts; push when a credential is used from a new address; optional push on app errors.
- **Lockdown** — one-click (or automatic, on new-address auth) suspension of the outbound callback relay, with a 1-hour suspend for planned new-device setup.
- **pjsip.conf** — read-only preview of what the panel generates.

The only hand-edited file is the bootstrap `.env` at the repo root (domain,
admin login, internal ARI secret — copy [deploy/.env.example](deploy/.env.example)).

## Build order (from spec §7)

1. VPS + Asterisk, one test phone endpoint, manual ARI originate → prove the missed-call entry appears with correct CLI (tests B, C).
2. Trunk-back seat + dialplan → prove a tapped missed entry rings out via VoIPstudio.
3. Webhook capture (test A) → adjust receiver payload constants → end-to-end with a real abandoned call.
4. Roll `reg.N.*` to remaining handsets; optional silent Alert-Info ring class.

## Things that must be checked on real hardware before trusting this repo

- The webhook payload semantics are built on **capture-proven facts from Query Tracker's `voip_webhook.php`** (same VoIPstudio feed): per-leg `call.missed` artifacts, `root_call_id` grouping, the `final` flag, bare-44 `src` format. Test A now only verifies the abandoned-call specifics — see [docs/test-plan.md](docs/test-plan.md).
- Asterisk's CANCEL on originate timeout is expected to carry no `SIP;cause=200`, but **test B verifies it on the wire** before rollout.
- The Alert-Info silent-ring parameter names in `phones/` need verifying against the UCS Admin Guide for the exact firmware on the VVXes.
